# Test Plan: TV Controller Project

## 1. 단위 테스트 범위 및 우선순위
- **숫자 입력 및 채널 변경 (High)**  
  - 단일 숫자 입력 후 OK  
  - 연속 숫자 입력 후 OK  
  - `0` + `7` → 7번 채널  
- **업/다운 버튼 동작 (High)**  
  - 검색 결과 없음 → 단순 ±1 이동  
  - 검색 결과 있음 → 목록 내 이동  
- **선호 채널 관리 (Medium)**  
  - 추가/삭제 동작  
  - 다음 선호 채널 이동 (순환 포함)  
- **검색 버튼 동작 (Medium)**  
  - 전체 채널 검색(Mock Tuner 활용)  
- **예외/경계 조건 (High)**  
  - 범위 초과 입력  
  - 빈 선호 목록에서 `NEXT_FAVORITE`  
  - 검색 결과 없음 상태에서 업/다운  

## 2. 경계값 케이스 목록
- 채널 범위: `0`, `99`  
- 입력: `0` + `7` → 7번 채널  
- 업 버튼: `99` → `0`  
- 다운 버튼: `0` → `99`  
- 선호 목록이 비어있을 때 `NEXT_FAVORITE`  
- 숫자 입력 중 다른 버튼 입력 시 버퍼 무효화  

## 3. 예외/특이 케이스 목록
- 채널 범위 초과 입력 (예: `100`, `-1`)  
- 빈 검색 결과 상태에서 업/다운 버튼 → 단순 ±1 이동  
- 선호 목록에서 삭제 시 빈 목록 처리  
- Mock Tuner 동작 검증 (`seek_ch`, `set_ch`, `get_current_ch`)  

## 4. 커버리지 목표 및 측정 전략
- **목표 커버리지**: 90% 이상 (라인/브랜치 기준)  
- **측정 도구**: `pytest-cov` + `coverage.py`  
- **전략**:  
  - 모든 PRD 시나리오를 테스트 케이스로 작성  
  - 경계값/예외 케이스를 별도 그룹으로 관리  
  - CI/CD 파이프라인에서 커버리지 리포트 자동 생성  
  - `gcov/lcov`를 활용하여 커버리지 시각화 및 누락 영역 분석  
  - 누락된 로직은 우선순위 기반으로 테스트 추가  

## 5. 개선 전략
- **테스트 코드 리팩토링**: 중복 제거, 파라미터화 활용  
- **테스트 클래스 분리**: SRP 준수 (숫자 입력, 업/다운, 선호 채널 등)  
- **헬퍼 함수 도입**: 반복되는 입력 시퀀스 처리 단순화  
- **지속적 커버리지 모니터링**: 커버리지 < 90% 시 빌드 실패 처리
