## 1. 프로젝트 개요

셋탑박스에서 리모컨 입력을 받아 채널을 관리하고, 외부 **Tuner** API를 통해 튜너를 제어하는 **TVController** 모듈을 TDD 방식으로 구현·검증하는 실습 프로젝트이다.

### 기술 스택

| 구분 | 도구 |
|------|------|
| 언어 | Python 3 |
| 테스트 | pytest |
| 커버리지 | pytest-cov, coverage.py |
| Mock | unittest.mock (`MagicMock`), 프로젝트 `MockTuner` |
| AI 규칙 | `.cursorrules` (프로젝트 루트) |

### 디렉터리 구조

```
TDD_TV_10/
├── src/
│   ├── remote_key.py      # RemoteKey enum
│   ├── tuner.py           # Tuner ABC, MockTuner
│   └── tv_controller.py   # TVController (핵심 로직)
├── test/
│   ├── test_tuner.py      # Tuner Mock 사용 예시
│   ├── test_tv_controller.py
│   └── test_golden_master.py
├── doc/                   # 요구 분석, 테스트 계획, 코드 품질
├── Report/                # 본 보고서

├── pytest.ini
├── requirements.txt
└── README.md
```

## 2. 구현 현황

### 2.1 모듈별 역할

| 모듈 | 설명 | 상태 |
|------|------|------|
| `RemoteKey` | 리모컨 키 enum (0~9, OK, UP, DOWN, SEARCH, ADD_FAVORITE, NEXT_FAVORITE) | 완료 |
| `Tuner` (ABC) | 외부 API 계약 (`seek_ch`, `set_ch`, `get_current_ch`) | 완료 |
| `MockTuner` | 테스트용 Fake/Mock 구현 | 완료 |
| `TVController` | 리모컨 입력 처리 및 Tuner 제어 | 완료 (일부 요구와 검증 갭 존재) |

### 2.2 TVController 내부 상태

| 상태 | 타입 | 용도 |
|------|------|------|
| `_processing_ch` | `str` | 숫자 입력 버퍼 |
| `_favorites` | `list[str]` | 선호 채널 목록 |
| `_search_results` | `list[str]` | 채널 검색 결과 |

### 2.3 핵심 API

```python
class TVController:
    def __init__(self, tuner: Tuner) -> None: ...
    def push_button(self, key: RemoteKey) -> str | None: ...
```

- 숫자 키: 버퍼에 누적, `None` 반환
- 확인(OK): 버퍼 채널을 Tuner에 반영 후 현재 채널 반환
- 기능 키: 각 `_handle_*` 메서드로 위임
- 그 외 키: 숫자 버퍼 무효화

## 4. 테스트 현황

### 4.1 테스트 파일 요약

| 파일 | 테스트 수 (대략) | 목적 |
|------|------------------|------|
| `test_tv_controller.py` | 13 | Controller 기능·경계 |

| `test_golden_master.py` | 1 | stdout 회귀 (Golden Master) |

### 4.2 테스트 완료율 (요구 시나리오 기준)

| 영역 | README 시나리오 | 테스트 커버 | 완료율 |
|------|-----------------|-------------|--------|
| 숫자 입력 | 5 | 3 | 60% |
| 선호 채널 | 4 | 3~4 | 75~100% |
| 채널 검색 | 1 | 1 | 100% |
| 업/다운 (검색 없음) | 3 | 3 | 100% |
| 업/다운 (검색 있음) | 3 | 1~2 | 33~67% |
| **전체 (가중)** | **16** | **11~12** | **약 69~75%** |

### 4.3 커버리지 목표

- **목표:** `src` 라인 커버리지 **90% 이상** (`.cursorrules`, `doc/requirements_analysis.md`)
- **측정 명령:**
  ```bash
  pytest --cov=src --cov-report=term-missing --cov-fail-under=90
  ```
- **본 보고서 작성 시점:** 실행 환경에 Python/venv 미구성으로 **실측 수치 미확보**. 코드·테스트 정적 분석 기준으로 `tv_controller.py` 주요 분기 대부분은 테스트에 포함되나, `_handle_next_favorite` 중간 케이스·검색 목록 다운/업 순환·연속 숫자 자동 반영 등은 **90% 미달 가능성** 있음.

### 4.4 Golden Master 테스트 이슈

`test_golden_master.py`는 `src/tv_controller.py`를 **실행 스크립트**로 가정하고 `tests/golden_master_expected.txt`와 비교한다.

| 이슈 | 설명 |
|------|------|
| 경로 불일치 | Golden 파일 경로 `tests/` vs 실제 테스트 디렉터리 `test/` |
| 실행 진입점 없음 | `tv_controller.py`에 `if __name__ == "__main__"` 블록 없음 |
| **권장** | Golden Master용 CLI 진입점 추가 또는 테스트를 `push_button` 시퀀스 기반으로 전환 |

`doc/code_quality_report.md` 요약:

| 우선순위 | 이슈 | 개선 방향 |

| 2 | 모호한 assert, 타입 힌트 | 명확한 기대값, 시그니처 type hint (Controller는 적용됨) |

| 4 | Magic String | 상수·fixture 정리 |
| 5 | 복잡 조건 | dataclass 기반 상태 표현 검토 |

### 구현 코드 강점

- Tuner 의존성 주입으로 테스트 용이
- 기능별 private handler 분리 (`_handle_up`, `_handle_favorite` 등)
- Python 3.10+ 스타일 type hint (`str | None`, `list[str]`)

### 잠재 결함·불일치

1. **연속 숫자 입력 동작:** README는 `1,2,3,4`만으로 12→34 변경을 기술하나, 구현은 **확인(OK) 전까지 Tuner 미변경**.
2. **`4,5,6` 시나리오:** 45 즉시 반영 및 이후 6 버퍼 무효화 규칙 미구현·미테스트.
3. **검색 결과 업/다운:** README 예시(15번에서 업→4) 전체 미검증.

## 8. 다음 레거시 프로젝트 Best Practice (5)

1. **README 시나리오 = 테스트 체크리스트** — numbered 요구마다 `@pytest.mark.parametrize` 또는 전용 테스트 1:1 매핑.
2. **외부 API는 ABC + Mock 고정** — Tuner처럼 제공 모듈은 인터페이스만 소유하고 테스트는 Mock/Fake로 격리.
3. **커버리지 CI 게이트** — `--cov-fail-under=90`을 PR/로컬 공통 스크립트로 고정.
4. **Golden Master는 실행 가능한 계약으로** — stdout 비교 전 CLI/`__main__`·경로·fixture 일치 확인.
5. **`.cursorrules`로 AI 일관성** — 절대 규칙·테스트·리팩터 기준을 코드베이스와 동기화.

## 11. 결론

TDD_TV 프로젝트는 **TVController 핵심 기능(숫자+확인, 선호 채널, 검색, 업/다운)** 이 구현되었고, pytest 기반 테스트로 주요 경로가 검증되었다. Cursor AI용 **`.cursorrules`** 로 개발·QA 규칙이 문서화되었다.
